# English

Personal English-learning tracker for **Geison** (Brazilian Portuguese speaker, FullStack JS developer).

An AI conversation partner ("English BOT") talks with him and updates this repo after every conversation. Once a week it generates a lesson from the accumulated data.

**Primary goal:** fix grammar mistakes and unnatural phrasing.  
**Secondary goal:** teach new vocabulary.  
Reviews use spaced repetition (Anki / SM-2 style) — see [docs/srs.md](docs/srs.md).

## Layout

```
README.md                      ← you are here
docs/srs.md                    ← exact spaced-repetition scheduling rules
sessions/YYYY-MM-DD.md         ← one log per conversation day
data/errors.json               ← recurring mistake patterns + SRS fields
data/mistakes.jsonl            ← one JSON line per mistake occurrence
data/top-mistakes-90d.md       ← auto: patterns ranked by count (last 90 days)
data/vocabulary.json           ← new / reviewing phrases + curated known terms
data/pronunciation.json        ← speech-to-text mishearings (pronunciation signals) + SRS
data/known-words.txt           ← auto: every word Geison used in sessions (sorted)
data/top-5000.txt              ← 5,000 most common English words (frequency order)
data/unknown-top-words.txt     ← auto: top-5000 words not yet in known-words
lessons/YYYY-Www.md            ← weekly lesson plans (ISO week)
lessons/_TEMPLATE.md           ← copy this when starting a new week
scripts/update-known-words.js  ← rebuilds known-words + unknown-top-words (no deps)
scripts/top-mistakes.js        ← rebuilds top-mistakes-90d.md from mistakes.jsonl
.github/workflows/…            ← daily + on sessions/ push: run scripts, commit if changed
```

Plain Markdown, JSON, and text. No app, no build. Word lists are maintained by a small Node.js script (stdlib only).

## Workflow (for the English BOT / agent)

### 1. After every conversation

1. Save a session log at `sessions/YYYY-MM-DD.md`:
   - Geison's messages under a `## Geison's message` heading (verbatim transcript)
   - Error table: category, what he said, correct version, rule
   - Pronunciation / STT mishearings → also add/update `data/pronunciation.json`
   - New vocabulary noted in the chat → `data/vocabulary.json`
2. Update `data/errors.json`:
   - Match new mistakes to existing patterns (`id`) when possible → bump `occurrences`, refresh examples
   - Otherwise add a new entry with SRS defaults (see below)
3. Append one line per occurrence to `data/mistakes.jsonl`:
   `{date, session, said, correct, pattern_id, category, severity}`
4. Update `data/vocabulary.json` for words/phrases he learned or clearly didn't know
5. Update `data/pronunciation.json` when STT clearly misheard a word (what was **heard** vs what he **intended**), with SRS fields
6. Optionally run `node scripts/update-known-words.js` and `node scripts/top-mistakes.js` (GitHub Actions also does this daily / on push)
7. Commit and push to `main`

### 2. Spaced-repetition defaults for new items

```json
{
  "ease": 2.5,
  "interval_days": 1,
  "repetitions": 0,
  "due_date": "<tomorrow YYYY-MM-DD>",
  "last_reviewed": null
}
```

Scheduling math lives in [docs/srs.md](docs/srs.md). When reviewing, update those five fields in place on errors, learning vocabulary, and pronunciation entries.

### 3. Once a week (lesson generation)

1. Copy `lessons/_TEMPLATE.md` → `lessons/YYYY-Www.md` (ISO week)
2. Pull the top serious / due errors from `data/errors.json` (and due vocab / pronunciation)
3. Write short explanations + 3–5 practice sentences per focus error
4. Add a quick vocab review section
5. Commit and push

### 4. During a review session

- Query items where `due_date <= today`
- Mark pass / fail and apply the SRS rules in `docs/srs.md`
- Prefer speaking/writing practice over multiple-choice

### 5. “Which common words don’t I know yet?”

Open [`data/unknown-top-words.txt`](data/unknown-top-words.txt): words from the top 5,000 frequency list that have not appeared in Geison’s own session text yet (still in frequency order). Regenerated by the script / Actions workflow — no AI needed.

### 6. “Which mistakes do I repeat the most?”

Open [`data/top-mistakes-90d.md`](data/top-mistakes-90d.md): patterns from `mistakes.jsonl` ranked by occurrences in the last 90 days (severity breaks ties). Rebuild with:

```bash
node scripts/top-mistakes.js
```

## Known words (programmatic)

`data/known-words.txt` is **not** hand-edited. It is rebuilt from Geison’s text only (the `## Geison's message` section in each `sessions/*.md` file):

```bash
node scripts/update-known-words.js
```

The script:

1. Scans all session files
2. Tokenizes Geison’s message text (lowercase, strip punctuation, skip numbers, light lemmatization)
3. Merges into `data/known-words.txt` (deduped, sorted)
4. Writes `data/unknown-top-words.txt` = `top-5000` minus `known-words` (keeps frequency order)

GitHub Actions (`.github/workflows/update-known-words.yml`) runs the same script **once a day** and **on pushes that touch `sessions/`**, then commits the two list files back to `main` if they changed.

## Frequency list source

[`data/top-5000.txt`](data/top-5000.txt) is the first **5,000 alphabetic** word types (frequency order) taken from:

- **Source:** [hermitdave/FrequencyWords](https://github.com/hermitdave/FrequencyWords) — `content/2018/en/en_50k.txt`
- **Corpus:** [OpenSubtitles 2018](http://opus.nlpl.eu/OpenSubtitles2018.php) token counts
- **License:** content under **[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)**; generator code under MIT (see upstream repo)

Non-alphabetic tokens (e.g. `'s`, `'t`) were skipped so the list stays usable for vocabulary gaps.

## Data file contracts (keep stable)

Agents should prefer updating existing entries over inventing new shapes.

| File | One entry = | Required fields |
|------|-------------|-----------------|
| `data/errors.json` | mistake pattern | `id`, `category`, `examples` (`said` / `correct`), `rule`, `first_seen`, `occurrences`, `severity`, + SRS |
| `data/vocabulary.json` | word or phrase | `id`, `term`, `status` (`learning` \| `known`), `notes`, `first_seen`, + SRS for learning items |
| `data/pronunciation.json` | STT mishearing | `id`, `heard`, `intended`, `context`, `first_seen`, `occurrences`, + SRS |
| `data/known-words.txt` | one word / line | lowercase, sorted — **generated** |
| `data/unknown-top-words.txt` | one word / line | frequency order — **generated** |

`severity` for errors: `high` | `medium` | `low`.

### Pronunciation entries

When speech-to-text writes something Geison did not mean, log it in `data/pronunciation.json` (and mention it in the session file):

```json
{
  "id": "pron-cursive-cursor",
  "heard": "cursive",
  "intended": "Cursor",
  "context": "\"you can use cursive for that\"",
  "first_seen": "2026-10-19",
  "occurrences": 1,
  "ease": 2.5,
  "interval_days": 1,
  "repetitions": 0,
  "due_date": "2026-10-20",
  "last_reviewed": null
}
```

These are pronunciation **signals**, not proof — use them for speaking practice with the same SRS schedule as errors.
